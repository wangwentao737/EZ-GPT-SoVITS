用独立整合包副本测试，将项目输入、日志和成品放在测试工作区。需要保留原样的旧包使用既有快照，或从一次性副本采集。核对测试前后的文件清单。改名以及修改 BAT 启动参数或端口的测试应分别进行。

启动需要采集的测试服务后，从项目根目录运行采集脚本。只检查主服务时可以省略 `--inference-port`。

```powershell
python tests/collect-engine-compatibility.py --engine .test/engine-new --output .test/capture-new --main-port 9874 --inference-port 9872 --source "归档来源与标识"
```

核对 `capture.json` 和 API 快照，确认监听属于该测试实例。逐项比对事件、参数顺序和类型、控件、返回结构及中止接口。快照记录接口和脚本证据。提交报告时引入经过检查的字段，移除本机路径等环境信息。

## 清单登记与回归

- 从当前清单复制新条目，填写唯一包 ID、显示名称、`identity_source`、`adapter` 以及主服务和快速推理脚本摘要。可以附上 BAT 摘要备查。有可信版本声明时附上 `upstream_version.value` 和 `upstream_version.source`。
- 每条能力填写 `operation`、`resources`、`result` 与报告链接。合成和训练类能力填写 `family`，转写填写 `language`，失败项可填写 `reason`。可在 `scripts` 填写当前操作所用脚本的摘要。未测试的组合省略或记录为 `unverified`。
- 递增 `revision` 并核对适用的 `ez_min` 与 `ez_max`。在设置导入清单，检查新包与 20261006 的选项、任务复核和切换。撤回登记时用新修订删除对应能力或更新结果。
- 本地验收后，将报告和 `compat/registry-v1.json` 合入上游仓库的 `main`。再用同一个 EZ 构建检查在线更新、重复检查和离线导入。
